# PRD V3 — 审批后的受控动作（路线图）

状态：未排期；需要独立风险与平台执行能力评审。V1/V2 不注册生产写工具。

## 场景

Case 调查后，工程师在宿主平台审批指定对象、参数与有效期的操作；平台动作服务执行并观察效果。Agent 提议和解释，不拥有审批权。

## 必需设计

Recommendation → Action Proposal → Permission Check → Approval → Execution → Verification。
Action 包含 actionId、来源任务/报告版本、对象、操作、参数哈希、风险等级、理由、审批策略、有效期、幂等键、执行回执、补偿方案及验证计划。修改任一对象或参数使旧审批失效。

执行前复查身份、对象当前状态、审批签名/有效期和并发条件。审批不能由模型文本代替。高风险操作按平台策略双人复核；重试不得重复生产变更。无可逆补偿的操作应明确停止条件与人工处理路径。

## 呈现与验收

在原分析面板增加动作记录与审批状态，实际生产操作由平台动作网关承接。动作状态与分析任务状态分离。验证结果使用 RESOLVED / PERSISTING / INCONCLUSIVE，不以 API 成功代替异常已解决。

验收包含过期审批、参数变化、撤权、重放、重复执行、网络失败、设备状态变化和验证不充分。先在仿真环境验证，再由业务方决定受控试点。
