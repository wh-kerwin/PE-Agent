# 用户旅程

| 步骤 | 工程师行为 | 系统行为与界面 |
|---|---|---|
| 发现 | 在原 Dashboard 筛选 Case | 保留列表筛选、排序、分页和滚动位置 |
| 触发 | 点击行末 AI 分析 | 立即打开 Drawer，显示 Case ID；提交 caseId，不要求写问题 |
| 等待 | 查看调查过程 | 202 返回任务；SSE 显示已完成、进行中、失败/跳过的查询 |
| 检查 | 阅读发现、时间线和假设 | 每项可展开证据与来源；缺数据显著提示 |
| 复核 | 接受、修正或标为待调查 | 保存独立 reviewStatus 和工程师结论；Helpful 不等于根因确认 |
| 归档 | 点击保存 Case Book | 保存报告版本与人工结论；失败可重试，不丢复核记录 |
| 返回 | 关闭 Drawer，继续处理其他 Case | 后台任务不取消，列表保留原状态 |

重复点击运行中的 Case 恢复已有任务；「重新分析」显式创建新任务。刷新后由 caseId 查询最新任务，先读取快照，再从 lastEventId 续传。旧 Case 版本报告显示「数据已更新，可重新分析」。

失败/无权限/不支持类型分别显示可理解原因；用户可关闭面板，不阻塞原平台工作。部分结果允许阅读和复核，但必须保留缺失证据标记。
